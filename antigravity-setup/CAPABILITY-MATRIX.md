# Capability matrix: what Antigravity (`agy`) can do for the plan automation

Measured on 2026-10-09 with **agy 1.3.2**, Windows 11, Node 20. Every probe ran in a **throwaway HOME** (`USERPROFILE` and `HOME` pointed at a temp folder) and a temp git workspace, with `gemini-3.8-flash-low` and one-line prompts. The real `~/.gemini` was never used or changed. 27 model runs were used in total (you approved about 25): 22 for the probes (one of them before the plan was approved: a `/usage` test), then 5 against the finished runner (3 smoke sessions, 2 sessions of one real run). Plus free commands (`agy models`, `agy agents`, `agy plugin list`, `agy mcp list`, `agy changelog`, bad-flag runs that fail before any model call).

Legend: YES = measured working. PARTIAL = works with a limit or workaround that was measured. NO = not available (measured or documented). UNKNOWN = could not be tested safely. Probe ids (P1 ...) are described in the appendix. "Claude reference" is the feature in `claude-plan-automation/FEATURES-REPORT.md`.

## Not proven or not possible (carried to the final report)

- Quota and credit errors (exit 3, `AGY_ERROR`) were never produced; the handling is documented behaviour tested only against the fake agy. `agy -p "/usage"` does not give reset times in 1.3.2.
- `--sandbox` could not be evaluated (the sandboxed shell had no `node`, `git` or `npm`).
- Interactive `ask_question`, several subagents at once, and a skill that must never auto-start cannot be tested headless.
- The isolated HOME works on Windows (sign-in through the OS credential store). macOS and Linux were not tested.
- The keep-awake and toast code is unchanged from the Claude runner and was not exercised.

## Found only by running the finished runner against the real agy

These were not visible in the probes; each led to a fix and a regression test.

1. **PowerShell wrote into the workspace.** `tests/real-run.mjs` (the real `run.mjs` and the real agy, one toy plan): session 1 did the work and the runner read `CHECKPOINT 1 OK` from the stream. Then the scope gate rejected `Microsoft/Windows/PowerShell/ModuleAnalysisCache` inside the toy repo. Cause, reproduced without a model: with no `AppData\Local` folder in the throwaway HOME, .NET returns an empty `LocalApplicationData` path and PowerShell writes its cache relative to the current folder (the workspace). Fix: the runner creates `AppData\Local`, `AppData\Roaming` and `Documents` in the session HOME (chaos test 01 checks it). The rollback worked as designed: the junk file was removed, saved as a `.patch`, and the retry resumed "after step 1" and passed every gate (the attempt was not counted, because a step had advanced).
2. **A failed gate sends the session exploring.** After that scope failure the second session spent 25 tool calls reading the runner's own source files and logs to understand the failure. Removing the cause (1) avoids it; the guard does not stop reads outside the workspace (see 3).
3. **agy lets a session read a file outside the workspace.** `tests/real-smoke.mjs`, second run: with only `command(*)` allowed, `view_file` of a file outside the workspace ran. Credentials are therefore protected by name (`.env`, `.ssh`, `.aws`, `.npmrc`, `.netrc`, keys, `.git/`), not by location. Whether `write_to_file` outside the workspace is allowed was not tested; files outside the repos are not snapshotted by any gate.
4. **The guard hook can time out on a busy machine.** In that same run three harmless calls (`node -v`, `git add -A`, `Invoke-WebRequest`) failed with `JSON hook ... failed` because several test suites were running at the same time. The call failed closed (agy refuses a call whose hook fails), so nothing unsafe happened. The hook timeout was raised from 15 to 30 seconds.
5. **Models obey a refusal.** agy tells the session "Do not attempt to circumvent this denial". In P3 (one command to run) the session simply stopped; in the smoke runs, which listed 10 to 13 calls, it carried on after every refusal, and the guard log shows 8 refusals for 6 forbidden items (a few were retried once). The runner's refusal reason adds that the shell is not off and the command should be skipped.
